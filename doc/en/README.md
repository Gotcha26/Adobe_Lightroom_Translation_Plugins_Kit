# Adobe Lightroom Translation Plugins Kit

A set of Python tools to internationalize your **Adobe Lightroom Classic** plugins effortlessly.
Developed to simplify multilingual management, this kit automates the extraction, application, and synchronization of translations.

---

## 📋 Who Is This For?

**Lightroom Plugin Developers**
- You want to make your plugin multilingual without manually managing translation keys.
- You prefer coding with hardcoded text and automating the conversion to the `LOC()` system.
- You want to easily maintain translations as your code evolves.
- You want to offer internationalization effortlessly without changing your coding habits.

**Translation Contributors**
- You want to translate a plugin into your language.
- You want to contribute via GitHub or simply share a translated file.
- The plugin doesn't have `TranslatedStrings_xx.txt` files yet? This kit will make creation easier.

---

## 🤚 Limitations

- **Does not modify the original language**: The Adobe SDK requires that a default string remains hardcoded in `.lua` files for fallback.
- **Does not translate automatically**: Translation remains manual (and that's better, context matters!).
- **Does not fix plumbing**: And doesn't make you rich either.

---

## 🎯 The Challenge of Multilingual Support

Internationalizing a Lightroom plugin involves:
- Extracting all text strings from code.
- Creating and managing unique keys for each text.
- Replacing hardcoded text with `LOC()` calls compliant with Adobe SDK.
- Synchronizing language files with each code modification.
- Avoiding duplicates, obsolete keys, and inconsistencies.

**Without tools, it's time-consuming and error-prone.**

---

## ✨ The Solution: 3 Complementary Tools

```
┌─────────────────────────────────────────────────────────────┐
│                   LocalisationToolKit.py                    │
│                       Main Menu                             │
└─────────────────────────────────────────────────────────────┘
                              │
         ┌────────────────────┼────────────────────┐
         ▼                    ▼                    ▼
    ┌─────────┐         ┌──────────┐        ┌──────────┐
    │Extractor│         │Applicator│        │Translator│
    └─────────┘         └──────────┘        └──────────┘
```

### 1. ***Extractor*** - String Extraction

Automatically scans your Lua code to extract all text strings.

**Input:**
```lua
local dialog = LrDialogs.confirm("Delete this photo?", "This cannot be undone")
```

**Output** (`TranslatedStrings_en.txt`):
```
"$$$/MyPlugin/Dialogs/DeleteConfirm=Delete this photo?"
"$$$/MyPlugin/Dialogs/DeleteWarning=This cannot be undone"
```

Generates unique keys following a reproducible and consistent *recipe*.

### 2. ***Applicator*** - Application in Code

Automatically replaces hardcoded strings with `LOC()` calls.

**Result:**
```lua
local dialog = LrDialogs.confirm(
    LOC "$$$/MyPlugin/Dialogs/DeleteConfirm=Delete this photo?",
    LOC "$$$/MyPlugin/Dialogs/DeleteWarning=This cannot be undone"
)
```

Creates automatic backups with restore capability.

### 3. ***Translator*** - Translation Synchronization

Keeps all your language files automatically up to date.

**Two main modes:**

#### INSTALL (first time)
Copies files generated by ***Extractor*** into your plugin and launches the initial conversion.

#### AUTO-SYNC ⭐ (for daily use)
Automatically synchronizes all present languages:
- Detects the latest extraction as reference.
- Adds new keys to all language files.
- Removes obsolete keys.
- Preserves all existing translations.
- Uses the original language by default for modified keys.

**This is the command to use 99% of the time.**

#### Advanced Commands
For specific needs, consult the [detailed Translator documentation](../../3_Translator/__doc/en/README.md).

## 🚀 Getting Started Guide

### First Time Use (converting an existing LrC plugin)

```
Hardcoded Lua Code
         │
         ▼  [1] python LocalisationToolKit.py → Extractor
TranslatedStrings_en.txt
         │
         ▼  [2] Translator → INSTALL
Files copied to plugin.lrplugin/
         │
         ▼  [3] Applicator
Code with LOC() + Active Translations
         │
         ▼  [4] Test in Lightroom
Functional Validation
```

**Commands:**
1. Configure plugin path: `[Option 6]`
2. Extract strings: `[Option 1] Extractor`
3. Install: `[Option 3] Translator → INSTALL`
4. Apply keys: `[Option 2] Applicator`
5. Test in Lightroom.

### Daily Maintenance (after code modifications)

```
Normal Development (hardcoded text)
         │
         ▼  [1] Extractor
New Extraction
         │
         ▼  [2] AUTO-SYNC ⭐
All language files synchronized
         │
         ▼  [3] Copy to plugin + commit
Ready for Translation
```

**Recommended Workflow:**
1. Develop normally with hardcoded text
2. Launch ***Extractor***: `[Option 1]`
3. Synchronize: `[Option 3] Translator → AUTO-SYNC`
4. Copy synchronized files:
   ```bash
   cp __i18n_tmp__/3_Translator/<timestamp>/TranslatedStrings_*.txt ./plugin.lrplugin/
   ```
5. Commit:
   ```bash
   git add .
   git commit -m "i18n: Update translation keys"
   git push
   ```

## 💡 Contributing Translations

### Via GitHub (recommended)

```
Fork repo → Clone → Translate → Pull Request → Merge
```

**Steps:**
1. Fork the plugin repository
2. Clone: `git clone https://github.com/YOUR_USERNAME/plugin.git`
3. Edit `plugin.lrplugin/TranslatedStrings_XX.txt` (XX = your language)
4. Translate the keys (compare with `TranslatedStrings_en.txt`)
5. Create a Pull Request:
   ```bash
   git add TranslatedStrings_fr.txt
   git commit -m "i18n(fr): Add French translation"
   git push
   ```

### Without GitHub

1. Download the `TranslatedStrings_XX.txt` file from the repository.
2. Translate the lines.
3. Send the file to the developer (email, message).
4. Use your translated version immediately locally!

```
plugin.lrplugin/
├── Info.lua
├── PluginCode.lua
├── TranslatedStrings_en.txt      ← English (reference/origin)
├── TranslatedStrings_fr.txt      ← French
├── TranslatedStrings_de.txt      ← German
├── TranslatedStrings_es.txt      ← Spanish
└── __i18n_tmp__/                 ← Temporary folder (auto-generated)
    ├── 1_Extractor/
    │   └── 20260131_120000/
    │       ├── TranslatedStrings_en.txt
    │       ├── replacements.json
    |       ├── spacing_metadata.json
    │       └── extraction_report.txt
    ├── 2_Applicator/
    │   └── 20260131_120500/
    │       ├── BACKUP/
    |       |   ├── File1.lua.bak
    |       |   └── File2.lua.bak
    │       └── applicator_report.txt
    └── 3_Translator/
        └── 20260131_121000/
            ├── TranslatedStrings_fr.txt
            ├── TranslatedStrings_de.txt
            ├── sync_report.txt
            ├── TRANSLATE_fr.txt
            ├── UPDATE_en.json
```

**About the temporary folder `__i18n_tmp__/`:**
- It is created automatically when running.
- Its name is configurable in settings.
- It can be safely deleted (it will be recreated if needed).
- Exclusion in your `.gitignore` file is automatically suggested.

## 🎓 Translation File Format

### Anatomy of a Key

```
"$$$/Piwigo/Dialogs/ConfirmDelete=Are you sure?"
 │    │       │         │            │
 │    │       │         │            └─ Default value
 │    │       │         └────────────── Descriptive name
 │    │       └──────────────────────── Category
 │    └──────────────────────────────── Plugin prefix
 └───────────────────────────────────── SDK Marker (mandatory)
```

**Structure:**
- `$$$/` : Mandatory marker, compliant with Adobe SDK.
- `Prefix` : Unique identifier for your plugin (ex: `Piwigo`).
- `Category/Key` : Organizational hierarchy (ex: `Dialogs/ConfirmDelete`).
- `=Default value` : Default text (code's original language).

### Placeholders (must be preserved!)

> 🇬🇧 _"Placeholder"_ → Space reserved for variable content

Strings may contain dynamic variables:
- `%s` : Text string.
- `%d` : Integer number.
- `\n` : Line break.
- `\t` : Tabulation.

**⚠️ IMPORTANT: Never remove or move placeholders!**

```
✅ Correct:
"$$$/Status=Albums created: %s, updated: %d"
→ "$$$/Status=Albums créés : %s, mis à jour : %d"

❌ Incorrect:
"$$$/Status=Albums créés, mis à jour"  (missing placeholders)
```

### Advice Directly in `TranslatedStrings_xx.txt` File

A tips block is systematically added to the header of each `TranslatedStrings_xx.txt` file, summarizing best practices and advice for translating without breaking anything.

### Advanced Workflow Markers

> ℹ️ Only with the **COMPARE** command (advanced usage):
> - `-- [NEW]` : New key to translate
> - `-- [NEEDS_REVIEW]` : Original value modified, retranslation needed

These markers **are NOT used** with **AUTO-SYNC** (daily workflow).

## ⚙️ Configuration

The `config.json` file stores your preferences:

```json
{
  "plugin_path": "D:\\Lightroom\\myPlugin.lrplugin",
  "output_base_dir": "",
  "temp_dir": "__i18n_tmp__",
  "auto_add_gitignore": true,
  "enable_flip_anim": false,
  "prefix": "$$$/Piwigo",
  "lang": "en",
  "last_extraction_dir": "",
  "last_used": ""
}
```

### Parameter Details

| Parameter | Description | Default Value |
|-----------|-------------|----------------|
| `plugin_path` | Absolute path to the plugin `.lrplugin` | *(empty)* |
| `output_base_dir` | Output directory (empty = next to script) | *(empty)* |
| `temp_dir` | Name of temporary folder created in plugin | `__i18n_tmp__` |
| `auto_add_gitignore` | Offer to add temporary folder to `.gitignore` | `true` |
| `enable_flip_anim` | Display animation on menu startup | `true` |
| `prefix` | Prefix for localization keys (ex: `$$$/Piwigo`) | `$$$/Piwigo` |
| `lang` | Default language of target LrC plugin source code | `en` |
| `last_extraction_dir` | Path of last extraction (internal use) | *(empty)* |
| `last_used` | Timestamp of last use (internal use) | *(empty)* |

Editable via: `[Option 6] Configure Plugin`

> **Note**: When `auto_add_gitignore` is enabled, the toolkit automatically detects if the plugin is in a Git repository and offers to add the temporary folder to `.gitignore` to avoid versioning generated files which can be numerous and non-essential to version.

## ❓ FAQ

### Do I need to translate all keys at once?
**No.** The Lightroom SDK uses a fallback system: if a key is missing, the default value (hardcoded) is displayed. You can translate progressively.

### Lightroom doesn't display my translations
Check:
1. The `TranslatedStrings_xx.txt` file is at the root of the plugin
2. The name matches your system language (ex: `TranslatedStrings_fr.txt` for French)
3. Complete Lightroom restart (not just "Reload Plugin")
4. The keys in the file match the code (search in `.lua` files)

### Can I manually edit the files?
**Yes!** `TranslatedStrings_xx.txt` files are plain text. Edit them with any editor.

### The temporary folder takes up space
***Applicator*** backups can be large. You can:
- Delete it via `[Option 5] Delete` or manually
- Exclude it from Git by adding `__i18n_tmp__/` to `.gitignore`
- It will be recreated automatically if needed

### How do I contribute or report a toolkit bug?
Use [GitHub Issues](https://github.com/Gotcha26/Adobe_Lightroom_Translation_Plugins_Kit/issues).

## 🎨 Complementary Tools (***Tools***)

### Restore (Option 4)
Restores original `.lua` files set aside before modification by ***Applicator***.
Backups are created automatically before any modification.

### Delete Temp Dir (Option 5)
Deletes `__i18n_tmp__/` to free up space.
Recommended after each major toolkit version.
